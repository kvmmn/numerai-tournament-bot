Numerai Winning OS - Visual System Map

A practical view of how your system runs daily: automation trigger, data sync, model training, evaluation, governance gate, and controlled submission.

Dual engine: MCP-first + NumerAPI fallback Human-governed submit gate Daily automation + monitoring reports

1) End-to-End Flow

Automation Trigger

Codex automation runs on schedule and starts daily runner.

Preflight

Checks auth, tools/models, and current round readiness.

Data Sync

Fetches required datasets and refreshes live data.

Train

Builds challenger model and saves artifact/checksum.

Evaluate

Computes correlation, Sharpe, drawdown, exposure.

Governance Gate

Approve, reject, or retry. Auto-submit only when enabled.

Submit

Uploads predictions to selected model(s), tracks per-model status.

Report + Inbox

Writes JSON/Markdown reports and surfaces findings in Codex.

MCP-First Engine

Use NUMERAI_MCP_URL and NUMERAI_MCP_AUTH
Discover tools via /api/v1/mcp/preflight
Tool mapping inferred or explicitly pinned by env
Run stages through /api/v1/mcp/run
mcp-auto submits only if automation/ENABLE_SUBMIT exists

NumerAPI Fallback

Uses NUMERAI_PUBLIC_ID + NUMERAI_SECRET_KEY
Runs local sync/train/evaluate/submit pipeline
Targets explicit models using NUMERAI_MODEL_NAMES
Any stage failure returns FAILED and report for triage

2) Daily Automation Rhythm

09:00
Monitor run executes mcp-dry-run and validates health.
11:30
Auto-gate run executes mcp-auto --strict.
Submit Gate
Without ENABLE_SUBMIT, it remains dry-run. With flag, submit is allowed.
After Run
Codex inbox receives findings; report artifacts stay on disk.

3) Failure and Recovery Paths

Auth missing -> preflight fails -> fix env -> rerun
MCP tool mismatch -> map tool names in env -> rerun
Model/data failure -> status FAILED -> inspect latest report
Submit blocked -> expected when gate file absent
